Why these markets: next goal, over/under totals, corners, bookings and player props are consistently the highest-volume in-play markets at leading sportsbooks — they are also precisely the micro-moment markets our overlay UX is designed for. Every market above is fully priceable and settleable from Opta data alone, keeping Stats Perform the single source of truth.

3. Live events — migration from polling to push (SDDP)

Today we poll MA1/MA3 every 60 seconds, which caps our market-suspension latency. Under the developer licence we will migrate the live pipeline to Sports Data Delta Push (SDDP) feeds:

Push feedReplaces (poll)Content / use in goal.live
MA1DP — Live ScoreMA1 pollingScore, match status, period, minute — drives match lifecycle, bet-window open/close
MA3DP — Match Events DataMA3 pollingTime-coded events (goals, corners, cards, penalties, VAR, substitutions) with player IDs and qualifiers — drives instant market suspension and on-chain settlement triggers
MA2DP — Match Stats Data—Live team stats (shots, possession, SOT) — overlay stat strip + player-prop settlement inputs
MA18DP — Match Events Aggregated Stats—Aggregated per-player event stats — player-prop markets (shots, fouls, cards per player)

Integration change on our side: we will add a persistent push-consumer service (long-lived connection per the SDDP integration guide) in front of our existing normalisation layer. Deltas are applied to match state in Supabase and fanned out to clients over our existing realtime channels — the downstream pipeline (odds engine, bet locking, smart-contract settlement) is unchanged. Target: event-to-market-suspension < 1 s from delta receipt (vs up to 60 s today). We request SDDP onboarding documentation and a sandbox/staging endpoint to validate connection management, recovery/replay and message ordering before the season starts.

How probability-driven betting works in goal.live

MA21 / forecast feeds ──► probability normaliser ──► goal.live pricing engine
                                                        │  decimal odds = 1 / p, plus transparent margin
                                                        ▼
                        overlay markets (odds shown with "powered by Opta model" fair-value)
                                                        │  user taps player / market → stake
                                                        ▼
                        bet locked (Supabase + on-chain audit) ──► MA3DP event settles market
                                                        ▼
                        smart-contract payout in USDC (oracle writes result from MA1/MA3)
  1. Pricing: model probability p → fair decimal odds 1/p → small transparent overround applied → published to all clients simultaneously via our realtime layer. Because our escrow is per-match pool based, probabilities can also drive a parimutuel view (pool share vs model fair value), which suits prediction-market regulation contexts.
  2. Repricing: every MA21 update (and every MA3DP event) triggers reprice; markets auto-suspend on goal/penalty/red-card deltas before reopening at new prices.
  3. Settlement: unchanged — MA3DP events (goal + scorer ID, corner, card) drive our existing oracle → smart contract settlement, so pricing and resolution share one Opta source of truth.
  4. Transparency: we display the model probability alongside odds — a differentiator only possible with model-based feeds rather than bookmaker prices.

5. Live video — Bet LiveStreams (La Liga 2026/27) + VOD

  • Live, ultra-low latency (the core ask): Bet LiveStreams delivered over Realtime Streaming (Phenix technology) — sub-second glass-to-glass latency with cross-device sync, for La Liga 2026/27 in our licensed markets. Our overlay wraps the stream player; market open/suspend states are gated to the synced video timeline. We request the playback SDK and the stream/data timestamp documentation.
  • VOD API (docs/rh/video(vod) — API reference & query parameters + shared authorisation guide): on-demand assets — goals, highlights, near-live clips — used for (a) instant replay cards in the overlay after a settled bet ("watch the goal you won on") and (b) match recap pages on our site. We will authenticate per the shared API Overview & Authorisation guide.
  • SmartReels (Broadcasts API): automated, personalised highlight reels and catch-up-to-live — lets a user joining mid-match catch up in 60 seconds, then land in the live synced stream with markets open. Strong retention feature for our beta cohort.

8. Coverage, auth & operational notes

  • Competition scope: Spanish La Liga, 2026/27 season (Tournament Calendar via OT2; fixtures via MA0/MA1). La Liga's top coverage tier gives full MA3 event detail incl. player qualifiers required for our settlement logic (per Soccer Coverage Tiers documentation).
  • Auth: existing OAuth 2.0 client-credentials flow against the SDAPI gateway; VOD/streaming auth per the shared API Overview & Authorisation guide; outlet keys per environment (staging/production).
  • Rate discipline: with SDDP push replacing live polling, our remaining REST polling is limited to model feeds (MA21 1/min in-play per guidelines, delta parameter _dlt used throughout) — well inside documented polling frequencies.
  • Compliance: betting operation runs under our licensing roadmap (EU, starting CZ); settlement-grade data usage confined to licensed markets; we follow feed-security best practice per the FAQs.
